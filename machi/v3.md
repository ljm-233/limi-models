# 马吉 Machi · v3（进行中，未定版）

> 2026-11-14 起。这一版换了整条数据管线，不再只调训练参数。
> 当前状态：三个支线模型已出，仍在加素材重训；**尚未定版**。

## 这一版改了什么

v2 的问题是「喂什么就学什么」：原图整张缩到 896 喂进去，SD1.5 只看得到 896 见方的窗口，细节全被缩没了。
v3 改成**从原生分辨率直接切窗口**，零缩放：

| 层 | 内容 | 尺寸 |
|---|---|---|
| 基础层 | 脸片 / 胸像 / 全身 / 整图 | 1024 / 768×1024 / 683×1024 / 长边 1024 |
| 瓦片层 | 按部位切 12 类 | 1024 见方，原生不足 1024 的块直接丢 |
| 视频层 | 一段 13 秒视频按 10fps 抽帧，130 张并入 | 2160×3840 |

## 三个支线

| 名字 | 数据 | 参数 | 用途 |
|---|---|---|---|
| machi_v3a | 2755 张基础图 | 896，3600 步，lr 1e-4 | 身份 + 构图（覆盖广） |
| machi_v3b | 1451 块瓦片 | 1024，2000 步，lr 5e-5 | 皮肤质感、部位细节 |
| machi_v3id | 1393 张脸片+胸像 | 896，6000 步，lr 8e-5 | 身份专项（每张看 4 轮多） |

组合用法：v3a 0.8 + v3b 0.3。
**v3b 到 0.5 会在脸上生红斑噪点**，0.3 干净，别超。

## 数据怎么筛的

1. 扫描：分辨率、清晰度、人脸、重复哈希 → 三档「全可用 / 仅瓦片 / 剔除」
2. 切图：骨架定位 + NudeNet 认内容（胸、生殖器、臀）；指端/下肢不可见就不切远端
3. 瓦片去重：跨图感知哈希
4. 质量闸：CLIP-IQA < 0.45 删除（GPU 上跑，一张 0.02 秒）
5. 脸片门禁：跟本人平均脸（ArcFace 512 维）相似度 < 0.45 删除
   —— 挡掉背景里的石膏雕塑、路人、虚焦

实测脸片相似度：中位 0.760，10% 分位 0.591。八套素材大概率同一人。

## 踩过的坑（给下一次的我）

- **同一张卡上不能一边训练一边跑别的推理**：质量闸上 GPU、ComfyUI 没关，都把训练顶爆过，两次都停在 95%
- 896 分辨率 + 1218 桶必爆；上限锁 1024，batch 2 配梯度累积
- protobuf 升到 7.x 会坏掉 mediapipe，锁 4.25
- 扫描脚本原来每次 `open(...,"w")`，跑多套会互相覆盖，改成追加写
- 数据集切图和训练不要并行，内存 14G 不够

## 命名规范（2026-11-15 定，以后只按这条）

格式：`v3` + 层 + 序号，**同一个系列内不另起 v4 / v5**

| 层 | 含义 | 现有 |
| --- | --- | --- |
| `id` | 身份层：只影响"像不像她" | `v3id1`（基线 0.676/7.33，在用）、`v3id2`（只喂脸片 0.573）、`v3id3`（非脸×2 / 脸×1，0.656） |
| `body` | 肢体层：身型与手 | `v3body1`、`v3body2` |
| `base` | 基底层：整图/换底模 | `v3base1`、`v3base2`（跑完登记） |

规则：
1. 序号在**同一条线内**递增，跨层不共用；用过的号不回收。
2. 换做法但不换层 → 只加序号（如 id2 → id3）。
3. 换底模 → 归 base 层，不占 id 的号。
4. 废止的版本保留文件、在文档里标"弃用"，不删不改名。
5. 老名字（`v3a`、`v3b`、`v3b1`、`v3id`、`v3wd14r2`、`machi_id_v1`、`machi_id_v2`）以硬链接保留兼容，不再新增这种写法。


## 2026-11-15 base_v2（写实底模）结果

`machi_base_v2`：majicmixRealistic_v7 当底模，喂 v3mix 同数据，2000 优化步 ≈ 4000 批次（2 轮，第一轮 18m45s）。

同一组提示词、同一种子（11/22/33/44）、`ohw2 woman, white hair, blue eyes, cosplay…`，768×1024：

| 版本 | 权重 | 相似度 | 纹理 |
| --- | --- | --- | --- |
| v3id1（SD1.5 基线） | 0.8 | **0.676** | 7.33 |
| v3base2 | 0.6 | 0.529 | 7.73 |
| v3base2 | 0.8 | 0.616 | 8.77 |
| v3base2 | 1.0 | 0.588 | 11.15 |
| v3base2 | 1.2 | 0.541 | 11.54 |

结论：换写实底模把"质感"拉上去了（纹理 7.3 → 8.8，权重 1.0 时到 11），但身份反而掉了（0.676 → 0.616），
权重再往上掉得更狠。也就是说**卡住身份的不是底模**，而是"脸只有 60–100 像素"这个信息量上限。
质感那一栏涨上去也有一部分是颗粒噪点，不是真的更像真人。

下一步只能走流水线层（v3id1 + FaceID 换脸），或把出图分辨率/构图改成脸部占比更大的特写。

## 2026-11-15 管线层（SD1.5 + IPAdapter FaceID）结果

做法：`machi_v3id1`（0.8）+ `ip-adapter-plus-face_sd15`（PLUS FACE 预设）+ 定妆照裁片当参考，768×1024。

| IPAdapter 权重 | 相似度 | 纹理 |
| --- | --- | --- |
| 0.25 | 0.663 | 4.67 |
| 0.35 | 0.646 | 4.60 |
| 0.45 | 0.614 | 4.67 |
| 基线 v3id1（无 IPAdapter） | **0.676** | **7.33** |

结论：SD1.5 上加 FaceID 也不划算——身份没超过基线，纹理掉到 4.6（IPAdapter 会把皮肤抹平）。
和之前 SDXL FaceID 那次（相似 0.74、纹理 4.5）合起来看，这是同一件事：
**FaceID 能把身份拉到 0.70 以上，但代价是质感垮掉**；SD1.5 连身份都拉不上去。

所以两条路都不通，剩下能动的只有：
1. 换更大画幅/更近构图，让脸在画面里的像素变多（信息量问题，不是模型问题）；
2. 后期把 SDXL-FaceID 的身份图和 v3id1 的质感图拼接（已有 0.74 的候选，缺质感）。

脚本：`scripts/gen_ipface_sd15.py`（SD1.5 管线层），`scripts/gen_faceid.py`（SDXL）


## 2026-11-15 构图实验：脸变大有没有用

同一 LoRA（v3id1，0.8），只把提示词从 "upper body" 改成 "close-up portrait, face focus"，832×1216：

| 构图 | 脸宽 | 相似度 | 纹理 |
| --- | --- | --- | --- |
| 上身（原基线） | 约 60–100px | **0.676** | 7.33 |
| 近景特写 | 459px | 0.654 | **9.20** |

结论：脸放大四倍，身份没有变好（0.654 < 0.676），质感倒是上来了。
说明"相似度上不去"不是纯粹的分辨率/像素量问题——更像训练数据的脸尺度分布把 LoRA 锁在了中景，
也可能相似度指标本身偏爱与训练裁片同尺度的脸。要验证得把指标换成多尺度（同一张图缩到 256 再算）。


## 2026-11-15 指标尺度偏差验证

疑问：0.676 的天花板会不会是"脸太小、指标测不准"。做法是取特写图，把整张按比例缩到脸宽≈80px（和上身图同量级）再算相似度：

| 原脸宽 | 原图相似 | 缩到 80px 后 |
| --- | --- | --- |
| 452px | 0.665 | 0.651 |
| 452px | 0.630 | 0.630 |
| 417px | 0.669 | **0.710** |
| 514px | 0.652 | 0.669 |

没有系统性下降（有一张还升了）。结论：**0.676 是真实的身份上限，不是测量尺度问题**。
另外体检了 2959 张裁片（64×64 灰度 std/mean），没有空图/纯色图，坏图没污染训练集。


## 2026-11-15 重要：指标换尺 + 拼脸管线跑通

### 指标的问题
原来的相似度是拿生成图和「训练集均值脸」比，永远给高分。换成真实照片当标准之后（真人互相之间 0.712）：

| 版本 | 对真人 | 对均值脸 | 纹理 |
| --- | --- | --- | --- |
| v3id1（旧基线） | **0.384** | 0.676 | 7.33 |
| v3base2（换底模） | 0.313 | 0.616 | 8.77 |
| v3id1 近景 | 0.431 | 0.654 | 9.20 |
| SDXL-FaceID 整图 | **0.704** | 0.470 | 5.69 |
| SD1.5 + IPAdapter | 0.455 | 0.641 | 4.64 |

结论：v3id1 的 0.676 是「像训练集平均值」，不是「像她」。真实身份分只有 0.384，而 FaceID 路线有 0.704 —— 已经到真人同一人的水平。

### 拼脸管线（新主线）
1. v3id1 出质感图（SD1.5）
2. SDXL + FaceID 在**脸部区域**做去噪重绘（`scripts/facefix.py`，denoise 0.55）
3. 只把重绘后的脸贴回原图（`scripts/paste_face_back.py`），身体和背景像素不动

| denoise | 对真人 | 纹理 |
| --- | --- | --- |
| 0.45 | 0.609 | 5.98 |
| **0.55** | **0.672** | 5.72 |
| 0.65 | 0.670 | 5.71 |
| 0.75 | 0.662 | 5.47 |

两个种子实测：0.671 / 5.77 与 0.690 / 5.79。身份从 0.384 抬到 0.67–0.69，代价是纹理从 7.33 掉到 5.8（脸部重绘会抹平细节）。

下一步要解决的是「怎么在保住 0.67 身份的同时把纹理拉回 7」：脸区提高分辨率重绘、或者重绘后叠一层高频细节。


### 1024 局部放大重绘（不如整脸重绘）
把脸裁出来放大到 1024 重绘、再缩回贴上：对真人 0.599 / 纹理 5.64；
整脸重绘 denoise 0.55 是 0.672 / 5.72。1024 那条反而更差——放大重绘会把脸的比例和光影推离原图。

**当前最佳配置**：`facefix.py`（denoise 0.55，weight 1.0）+ `paste_face_back.py`，两个种子 0.671 / 0.690，纹理 5.8。

## 2026-11-15 数据侧三次对照（全部没超过 v3id1）

同一组提示词、同一组种子（11/22/33/44）、LoRA 权重 0.8，只换 LoRA。指标：insightface 512 维余弦 vs 人脸质心；纹理 = 512px 灰度 Laplacian 均值。

| 版本 | 做法 | 相似度 | 纹理 |
| --- | --- | --- | --- |
| `machi_v3id1` | 现役基线，全部裁片 + 触发词 | **0.676** | 7.33 |
| `machi_v3wd14r2` | WD14 打标（2659 条描述）再训 | 0.639 | 8.08 |
| `machi_v3face` | 只喂脸片（753 张） | 0.573 | 7.51 |
| `machi_v3mix` | 非脸裁片 2 次 / 脸片 1 次，6000 步 | 0.656 | 6.19 |

结论：**数据侧没有剩余空间**。
- 加标注（WD14）不涨身份，纹理升一点但相似掉 0.037；
- 只见脸会让模型学成"一张标准漂亮脸"，本人特征反而淡了（下颌、脸型被拉平）；
- 脸片降权没解决这个问题，只是回到"靠构图猜"，纹理还退到 6.19（更塑料）。

判断：0.68 是 SD1.5 + 512 原生分辨率下这类素材的天花板，脸在画面里只占 60-100 px，
ArcFace 能认出的信息就那么多。继续调数据权重没有意义。
